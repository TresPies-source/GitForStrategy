# Reframe Before Spec

*Specs lock you in. Reframes free you up.*

## What it is

Before writing a spec, ask whether the question itself is the right one. A reframe changes which problem is worth solving.

## Why it matters

Sometimes the most valuable output of a planning stretch is not a spec but the reframe that changes what gets specified.

## The pattern

1. State the original question.
2. Ask: what question should we have asked instead?
3. Write it down as "Original question: X → Reframed question: Y."
4. Spec the reframed question, or say why the original stands. Don't force a reframe.

## Revisit when

You are about to spec a new integration or partnership. Every route in a scout feels like the same route.

## What it refuses

Specifying the first framing because it arrived first.
